# Electric Vehicle Control Unit (AKS) — STM32F407

**English** | [Türkçe](README.tr.md)

Firmware for the vehicle control unit ("AKS" — *Araç Kontrol Sistemi*) of an
electric vehicle built for Teknofest by the Kastamonu University Electric Vehicle
Team. A single STM32F407VET6 reads the motor controller, the battery management
system and the on-board charger over three CAN buses, drives the vehicle's
lighting and safety relays, and streams telemetry to a Raspberry Pi dashboard.

## System Architecture

```
Kelly KLS7245HC  ──CAN1 250 kbps (29-bit)──┐
(motor controller)                          │
TommaTech / JK   ──CAN2 500 kbps (11-bit)──┤
BMS (Pylontech)                             ├──► STM32F407VET6 ──UART 115200──► Raspberry Pi 5
Emerson R48-1800 ──CAN 125 kbps──► MCP2515 ─┤      168 MHz        JSON / 100 ms  (Python dashboard)
(on-board charger)            (SPI3 bridge) │
Opto-isolated inputs ───────────────────────┤  indicator stalks, headlights, doors, brake …
Relay board (active-low) ◄──────────────────┘  indicators, headlights, wiper, brake light,
                                               main contactor, warning buzzer/flasher
```

Both on-chip CAN peripherals are used by the motor controller and the BMS, so the
charger is connected through an external **MCP2515** CAN controller over SPI.

## Features

- **Three CAN buses** — Kelly motor controller (CAN1), BMS using the Pylontech
  protocol (CAN2), Emerson charger through the MCP2515 (SPI3)
- **Vehicle control logic** — turn signals (0.7 s blink, last selected wins),
  hazard lights, headlights, wiper, brake light, door switches
- **Safe start-up** — all inputs ignored and all relays released for the first
  second, so relays do not chatter while the opto-isolator supply settles
- **Charger detection without broadcast frames** — the Emerson charger does not
  transmit on its own, but it *acknowledges* our frames; plug-in is detected from
  the MCP2515 **transmit error counter (TEC)** behavior, with debounce and hold-off
  timers against false triggers
- **Contactor state machine** (drive → charging → exit wait → pre-close) — cuts
  power to the motor controller while charging, so the vehicle cannot move
- **Warning relay** (buzzer + flasher) — triggered when BMS communication is lost
  (5 s of silence, after a 15 s start-up grace period), battery temperature leaves
  the −15 °C … 55 °C range, the motor reaches 100 °C or the controller 80 °C, or the
  NTC sensor exceeds 50 °C; further conditions (motor controller loss/fault, BMS
  protection flag, low state of charge) are implemented and can be enabled with a
  `#define`
- **Telemetry** — a JSON line every 100 ms to the Raspberry Pi dashboard
  (speed, currents, SOC, temperatures, relay/contactor state, CAN diagnostics)

## Hardware

| Part | Role |
|---|---|
| STM32F407VET6 (F4VE board) | Vehicle control unit, 168 MHz |
| Kelly KLS7245HC | Motor controller |
| TommaTech / JK BMS | Battery management (Pylontech CAN protocol) |
| Emerson R48-1800 + MCP2515/TJA1050 | On-board charger and SPI-CAN bridge |
| Relay board (active-low) + opto-isolated inputs | Lighting, wiper, contactor, warning |
| Raspberry Pi 5 | Dashboard (reads the UART telemetry) |

## Building and Flashing

1. Open the project in **STM32CubeIDE** (double-click the `.ioc` file or import the folder)
2. **Project → Clean…**, then **Build** (Ctrl+B)
3. Flash to the board with **Run/Debug** (ST-Link)

> The BOOT0 jumper must be on **GND** for normal operation.

The application code lives in `Core/Src/main.c`, inside the `USER CODE` sections;
the rest is code generated by STM32CubeMX and the ST HAL/CMSIS drivers.
